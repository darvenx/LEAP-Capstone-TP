Sprint 3 Trade Database

A normalised PostgreSQL schema: 16 numbered migrations, one concern per file, applied in order and never edited after review. Two identical one-command setup paths (Docker and local psql) seed the same rows and run a probe suite of named queries plus required rejection tests.

Entity relationship model

Cross-row integrity, enforced in the database

Single-column CHECK constraints can't stop an order being opened against a suspended account, or a working order referencing a delisted instrument, so those rules are triggers, meaning no future service can violate them even through a bug.

CREATE OR REPLACE FUNCTION enforce_order_is_allowed()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    SELECT status INTO account_state
    FROM accounts WHERE id = NEW.account_id;

    IF account_state <> 'ACTIVE' THEN
        RAISE EXCEPTION 'orders require an ACTIVE account'
            USING ERRCODE = '23514';
    END IF;
    -- terminal orders may keep a since-delisted instrument
    IF NEW.status <> 'NEW' THEN RETURN NEW; END IF;

    SELECT tradable INTO instrument_tradable
    FROM instruments WHERE id = NEW.instrument_id;
    IF NOT instrument_tradable THEN
        RAISE EXCEPTION 'a NEW order requires a tradable instrument'
            USING ERRCODE = '23514';
    END IF;
    RETURN NEW;
END; $$;

Design discipline

  • Money is decimal, never floating point.
  • Delisting an instrument is a flag, never a row deletion, so order history stays intact.
  • Idempotency key on orders is a real UNIQUE constraint (23505), not just an app-layer check.
  • Two account identifiers on purpose: a numeric key for the API/JWT, a string reference for support calls.

Pure transform, one reason code per outcome

def _parse_iso_date(value: Any) -> dt.date | None:
    # date.fromisoformat is strict, rejects 09/07/2026
    try:
        return dt.date.fromisoformat(value)
    except ValueError:
        return None

def _clean_volume(value: Any) -> int | None:
    """Volume is nulled when negative or absent."""
    if value is None or isinstance(value, bool):
        return None
    v = int(value)
    return v if v >= 0 else None  # row kept, volume dropped

Sprint 5 Domain Engine

Plain Java 21, zero framework dependencies beyond jakarta.validation-api, enforced by the Maven Enforcer plugin's bannedDependencies rule so Spring, a servlet API or a JDBC driver fail the build the moment one reaches the dependency tree, even transitively. This is the package Sprint 6 will absorb as source into the Trade REST API, unmodified.

Class model

Order placement sequence: all 8 rules, first failure wins

Money never goes negative: checked before it's touched

public void debit(BigDecimal amount) {
    BigDecimal normalized = Money.normalize(requirePositive(amount));
    if (cashBalance.compareTo(normalized) < 0) {
        throw new InsufficientFundsException(
            accountId, normalized, cashBalance);
    }
    cashBalance = cashBalance.subtract(normalized); // only reached if it can afford it
}

Money is BigDecimal, normalized to two decimal places, never a double, so a thousand trades can't drift a balance out by a hundredth of a penny.

Eight rules, evaluated in order, first failure wins

public Order evaluate(PlaceOrderRequest request, Account account,
                       Instrument instrument, Position position) {
    // Rule 1: the account must exist.
    if (account == null) throw new AccountNotFoundException(request.accountId());

    // Rule 2: the account must be ACTIVE.
    if (!account.isActive())
        throw new AccountNotActiveException(account.getAccountId(), account.getStatus());

    // Rule 3: the instrument must exist and be tradable.
    if (instrument == null || !instrument.isTradable())
        throw new InstrumentNotFoundException(request.symbol());
    // ... rules 4-8: quantity, price, funds, holdings, idempotency key
}
